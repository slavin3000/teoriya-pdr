# Как выложить «Теорія ПДР: тести» в Google Play

Пошагово, от архива до приложения в магазине. Шаги 1–4 — сборка и проверка на телефоне (бесплатно, ~30 минут). Шаги 5–10 — Google Play (взнос $25, проверка личности, обязательный закрытый тест 14 дней).

---

## 1. Залить проект на GitHub

1. Заведите аккаунт на github.com (если нет).
2. Установите **GitHub Desktop** (desktop.github.com) и войдите в аккаунт.
   Через сайт загружать неудобно: в проекте больше 300 файлов, а веб-загрузка берёт до 100 за раз.
3. Распакуйте `teoriya-pdr.zip` в удобную папку.
4. GitHub Desktop → **File → Add local repository** → выберите распакованную папку `teoriya-pdr` → он предложит **create a repository** → Create.
5. Внизу слева нажмите **Commit to main**, затем сверху **Publish repository**.
   * Галочку **Keep this code private** можно снять (публичный репозиторий = бесплатная страница политики конфиденциальности на GitHub Pages, шаг 5) или оставить (тогда политику разместите в другом месте, например в Google Sites).

> Ключ подписи (`upload-key.jks`) в репозиторий **не кладите** — он в отдельном архиве и уже исключён в `.gitignore`.

## 2. Добавить ключ подписи в секреты репозитория

На странице репозитория: **Settings → Secrets and variables → Actions → New repository secret**. Создайте четыре секрета (значения — в `upload-key/credentials.txt`):

| Имя секрета | Значение |
|---|---|
| `ANDROID_KEYSTORE_BASE64` | всё содержимое файла `upload-key.base64.txt` (одна длинная строка) |
| `ANDROID_KEYSTORE_PASSWORD` | пароль из credentials.txt |
| `ANDROID_KEY_ALIAS` | `upload` |
| `ANDROID_KEY_PASSWORD` | тот же пароль |

Без секретов сборка тоже пройдёт, но соберётся только отладочный APK — для Google Play он не подходит.

## 3. Собрать приложение

1. Вкладка **Actions** → слева **Android build** → справа **Run workflow** → Run.
   (Сборка запускается и сама при каждом коммите в main.)
2. Через 5–10 минут появится зелёная галочка. Откройте запуск → внизу **Artifacts → teoriya-pdr-android** — скачается zip:
   * `teoriya-pdr-1.0.0.aab` — **для Google Play**;
   * `teoriya-pdr-1.0.0.apk` — подписанный APK, чтобы поставить на свой телефон;
   * `teoriya-pdr-1.0.0-debug.apk` — отладочный.

Если сборка красная — откройте упавший шаг, скопируйте последние 30–40 строк лога и пришлите мне.

## 4. Проверить на телефоне

Перекиньте `teoriya-pdr-1.0.0.apk` на Android-телефон, откройте, разрешите установку из этого источника. Проверьте:

- [ ] иконка и название «Теорія ПДР: тести», синий экран запуска;
- [ ] верх экрана не залезает под статус-бар и вырез камеры, низ — под жесты;
- [ ] билет «Навчання» до конца, результат, прогресс сверху обновился;
- [ ] начать билет → свернуть приложение → открыть: билет на паузе, продолжается с того же места;
- [ ] системная кнопка «Назад» во время билета ставит паузу, на главной — закрывает приложение;
- [ ] «Зберегти прогрес у файл» открывает меню «Поделиться»; «Відновити з файлу» принимает этот файл;
- [ ] тёмная тема телефона → приложение тоже тёмное;
- [ ] режим полёта — всё работает без интернета.

## 5. Политика конфиденциальности (обязательна для Google Play)

Текст готов: `docs/privacy.html` (украинский + английский).

1. Проверьте строку «Контакти» — там указан `slavin3000@gmail.com`. Эта страница будет публичной; если хотите отдельный адрес для приложения, замените его в двух местах файла.
2. Публичный репозиторий: **Settings → Pages → Source: Deploy from a branch → Branch: main, папка /docs → Save**. Через минуту страница будет по адресу
   `https://ВАШ_ЛОГИН.github.io/teoriya-pdr/privacy.html` — откройте и убедитесь, что открывается.
3. Приватный репозиторий: скопируйте текст на любую публичную страницу (например, Google Sites) и используйте её адрес.

## 6. Аккаунт разработчика Google Play

1. play.google.com/console → создать аккаунт разработчика → **Личный (Personal)** → разовый взнос **$25**.
2. Подтверждение личности документом, телефона и почты; Google также попросит подтвердить доступ к реальному Android-устройству через приложение Play Console. Проверка занимает от нескольких часов до нескольких дней.
3. Важно для новых личных аккаунтов: перед выпуском в открытый доступ обязателен **закрытый тест — минимум 12 тестировщиков, 14 дней подряд** (шаг 8).

## 7. Создать приложение и заполнить анкеты

**Все приложения → Создать приложение**: название `Теорія ПДР: тести`, язык по умолчанию **українська (uk-UA)**, «Приложение», «Бесплатное», подтвердить декларации.

Тексты и картинки для страницы в магазине — в `store/listing-uk.md`, `store/icon-512.png`, `store/feature-graphic-1024x500.png`, `store/screenshots/1–5.png`. Категория — **Образование**.

Раздел **Политика → Контент приложения** — ответы:

| Анкета | Ответ |
|---|---|
| Политика конфиденциальности | ссылка из шага 5 |
| Доступ к приложению | Все функции доступны без особого доступа (логина нет) |
| Реклама | Нет рекламы |
| Возрастной рейтинг (IARC) | категория «Справочные, новостные или образовательные»; на все вопросы о насилии, сексуальном контенте, языке, наркотиках, азартных играх, общении пользователей, передаче местоположения, покупках — **Нет**. Ожидаемый рейтинг — 3+ / PEGI 3 |
| Целевая аудитория | **18 лет и старше** (можно добавить 16–17; младше 13 не выбирайте — иначе включатся требования программы для детей) |
| Новостное приложение | Нет |
| Безопасность данных | «Собирает или передаёт ли приложение данные пользователей?» → **Нет**. Итог: данные не собираются и не передаются |
| Рекламный идентификатор (Advertising ID) | Не используется |
| Государственные приложения | Разработано государством или от его имени? → **Нет** |
| Финансовые функции, здоровье | Нет / не относится |

Описание уже содержит то, что Google требует от приложений с госинформацией: явную пометку, что приложение неофициальное и не связано с МВС/ГСЦ, и ссылки на первоисточники.

## 8. Закрытый тест (12 человек × 14 дней)

1. Для себя сначала удобно **Тестирование → Внутреннее тестирование**: загрузить `.aab`, добавить свою почту, поставить из Play — без ожидания проверки.
2. **Тестирование → Закрытое тестирование** → создать трек → **Создать выпуск** → загрузить `teoriya-pdr-1.0.0.aab`. При первой загрузке согласитесь на **подписание приложений в Google Play** (Play App Signing) — по умолчанию.
3. Тестировщики: список из **не менее 12 адресов Google-аккаунтов** (друзья, родные, коллеги). Отправьте им ссылку участия из Play Console: каждый должен нажать «Стать тестировщиком» и установить приложение.
4. Отправьте выпуск на проверку. Все 12 должны **оставаться в тесте 14 дней подряд** — попросите никого не выходить.
5. Через 14 дней: **Панель управления → Запросить доступ к рабочей версии** (Apply for production). Ответьте на вопросы о тесте: сколько было тестировщиков, какие отзывы, что исправили. Ответ — обычно до 7 дней.

## 9. Выпуск в открытый доступ

**Рабочая версия → Страны и регионы** (Украина + по желанию другие) → **Создать выпуск** → тот же `.aab` (или новее) → отправить на проверку. Проверка — от нескольких часов до нескольких дней.

## 10. Обновления

1. В `package.json` увеличьте `"version"`: `1.0.0` → `1.0.1` (или `1.1.0`). Из версии сам считается код сборки (1.0.1 → 10001), а Google Play принимает только код больше предыдущего.
2. Commit + Push в GitHub Desktop → Actions соберёт новый `.aab`.
3. Play Console → нужный трек → Создать выпуск → загрузить → на проверку.

## Ключ подписи — храните бережно

`upload-key.jks` + пароль — это ваша «подпись» для загрузки обновлений. Сохраните их минимум в двух местах (менеджер паролей + флешка/облако) и не публикуйте. При Play App Signing потерянный ключ загрузки можно заменить через поддержку Google Play, но это занимает время.

## Что ещё стоит знать

* **Права на содержимое.** Вопросы, картинки и таблица ответов взяты из материалов ГСЦ МВС, цитаты — из текста ПДР. Подобные тренажёры в Google Play есть, но я не юрист: если сомневаетесь насчёт использования картинок, уточните у юриста или в ГСЦ МВС.
* **Регистрация разработчиков Android (2026–2027).** Google вводит обязательную проверку разработчиков для установки приложений на сертифицированные телефоны. Для приложений из Google Play её закрывает проверка личности в Play Console (шаг 6). Если будете раздавать APK в обход магазина, следите за правилами в своей стране.
* **Кнопка «Чому?»** уже заложена: как только появится файл `src/explain.json` с пояснениями (формат описан в README), она сама появится под ответами после следующей сборки.
